# Agent Studio: свои и чужие персонажи

Проверено по текущему исходному коду. Наличие возможности в исходниках не
подтверждает установку этой версии на конкретном сервере.

## Какие ключи за что отвечают

- Grok/OpenAI/DeepSeek или подписка Codex — модель и её оплата.
- ElevenLabs — голос и его оплата.
- MCP credential — доступ к серверу и персонажам. Ключ модели не даёт прав на NPC.

## Свои персонажи — существующий интерфейс

1. В Agent Studio открыть шестерёнку → Servers, указать имя и HTTPS `/mcp` endpoint.
2. Получить код подключения и подтвердить его в авторизованном игровом клиенте
   (Escape → подключение Agent Studio). Обе стороны должны поддерживать pairing.
3. Выбрать агента → значок подключения → сервер → Connect → доступный персонаж.
4. Настроить модель/голос выбранного агента и явно нажать Play.
5. Stop освобождает attachment и управление. Не использовать один NPC для двух
   одновременно работающих агентов.

Этот credential привязан к игроку. Назначенные ему персонажи определяются
сервером. Подтверждение из аккаунта администратора НЕ превращает его автоматически
в глобальный административный credential: в pairing пока нет выбора такой роли.

## Любые персонажи — существующий серверный механизм

Доверенный MCP-клиент может использовать административный Bearer-токен `/mcp`.
Он хранится в `hexlive-mcp.txt` рядом с save path, выбранным параметрами процесса
сервера; точный путь определяется конфигурацией сервиса, а не местом игрового NPC.
Это не пароль веб-админки и не ключ модельного провайдера.

Клиент передаёт `Authorization: Bearer <MCP credential>` только по HTTPS.
С этим токеном сервер не применяет фильтр назначений игрока к `list_colonists`
и NPC-инструментам. Затем клиент выбирает npcId и использует штатные attachment
и action lease. Занятый/мёртвый NPC и прочие игровые ограничения остаются в силе.
Передача управления не делает NPC собственностью игрока и не переводит его лагерь.

Глобальный токен обладает широкими правами; не выдавать его обычным игрокам,
не вставлять в промпт, JSON профиля, чат, URL, скриншоты или общий архив.
В текущем механизме разные агенты могут использовать один такой credential,
но это НЕ даёт индивидуального отзыва прав: это общий административный секрет.

## Администратор — интерфейс Agent Studio

1. Шестерёнка → Servers. Назвать подключение, например «Production — администратор».
2. Указать HTTPS `/mcp` endpoint доверенного сервера.
3. Включить «Администратор — доступ к чужим персонажам».
4. В скрытое поле вставить существующий административный MCP-токен сервера.
   Не использовать здесь ключ модели или пароль веб-админки.
5. Нажать «Проверить и сохранить доступ». Приложение читает world_status и
   list_colonists; только после успеха сохраняет токен в системном хранилище.
6. У выбранного агента нажать значок соединения, выбрать это подключение,
   нажать Connect и выбрать NPC. Запуск модели — только отдельной кнопкой Play.

Можно хранить два подключения к одному endpoint: «Мои персонажи» через pairing
и «Администратор» через MCP-токен, выбирая их отдельно для Маши, Ники и других
профилей. Разные секреты имеют разные ссылки в системном хранилище. Неуспешная
проверка не перезаписывает ранее сохранённый ключ. Сервер и выбранные NPC
всё равно проверяют полномочия на каждом вызове.

## Будущее ограничение административных полномочий

Для дальнейшей раздачи доступа другим людям нужны отдельные отзываемые credentials
с ограниченным списком npcId/действий. Это новая серверная функция, не свойство
нынешнего глобального токена. Административные права в рамках правки дизайна
не выдавались и credentials не извлекались.
