# #488 — выбор персонажа и follow через HTML-меню

Регрессия #348: HTML-ростер правильно вызывал `NpcSelection.Activate`, но
`RtsCameraController.LateUpdateCore` выходил при `RuntimeWindow.BlocksWorldInput`.
После включения HTML этот флаг держится всё время наведения на меню. Запрос
Follow оставался невыполненным до ухода курсора с карточки.

Камера теперь продолжает обновлять rig и явное кадрирование при закрытом
мировом вводе. Ввод панорамирования, вращения, зума, рамки и кликов при этом
не обрабатывается. Первый выбор остаётся selection-only, повтор включает
follow, смена цели отцепляет прежнее слежение. Правило закреплено в §123.1.

Во время проверки создания настоящего `CharacterPanel` также обнаружено
запрещённое Unity создание `VisualElement` в инициализаторе поля
`CharacterPanel.HtmlInventory`. Scratch-элемент теперь создаётся при первом
построении статистики предмета, на UI-пути, без подавления исключения.

## Дополнение: все UI-гейты и переключение слежения

Повторная read-only проверка публичной страницы 2026-10-18 17:47 UTC показала
`Build/player-bc97a818f.loader.js`. Предыдущий commit `8986363ce951db1c23f090641ea0fde5ca35e6f0`
не входит в этот source commit: описанное игроком поведение всё ещё ожидаемо
в опубликованном старом Player. Обновление страницы не доставит код,
который ещё не опубликован.

В актуальном исходнике оставался общий выход при
`AdminVoicePanel.BlocksGameInput`: он останавливал rig при открытом админском
окне и в кадре его закрытия. Фокус HTML-текста при указателе вне документа
также не блокировал клавиатурный pan. Расширенный тест до исправления
воспроизвёл отцепление через WASD при текстовом фокусе (`Orbit → Free`).
Первый запуск расширенной фикстуры остановился на неоднозначном `MouseButton`
из двух namespaces; alias исправлен до этого воспроизведения.

Теперь `PointerBlockedForWorld()` и `HtmlUi.TextInputFocused` образуют общий
гейт ввода для Free/Orbit. Обновление target и ApplyRig продолжается каждый
кадр. Из камеры убран early return админского окна; сам UI сохраняет
владение Escape и закрывающим жестом. Guards перетаскивания и мировых кликов
не отключались.

Игрок отдельно подтвердил третий клик: первый выбирает, второй включает
follow, третий по тому же субъекту/набору отключает. При отключении выбор
сохраняется, pending frame отменяется, камера остаётся на фактическом pivot.
Четвёртый клик снова включает follow. Явный `RequestFrame` сохраняет прежний
смысл кадрирования. Нажатие на другого персонажа остаётся selection-only.
Проверки нового жеста также обнаружили остаточное движение после отключения
(в первом прогоне 0.0972 wu). Переход должен сохранять фактические сглаженные
параметры и обнулять их скорости. Усечение высоты свободного pivot тоже
перемещало кадр на неровном рельефе: в фикстуре настоящий offset равен
−0.16999 wu, а старый код заменял его нулём. Offset теперь наследуется точно.
Трасса после исправления показывает нулевое перемещение на трёх следующих
шагах. Тест проверяет фактическую камеру, а не только выход из режима Orbit.
Промежуточные красные прогоны сохранены и не считаются успешными. Внешний
pan-тест также явно освобождает UITK pointer owner и ставит указатель в мир:
координата (0,0) внутри нижней панели не является вводом вне UI.
