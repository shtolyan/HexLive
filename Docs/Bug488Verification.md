# #488 — выбор персонажа и follow через HTML-меню

Регрессия #348: HTML-ростер правильно вызывал `NpcSelection.Activate`, но
`RtsCameraController.LateUpdateCore` выходил при `RuntimeWindow.BlocksWorldInput`.
После включения HTML этот флаг держится всё время наведения на меню. Запрос
Follow оставался невыполненным до ухода курсора с карточки.

Камера теперь продолжает обновлять rig и явное кадрирование при закрытом
мировом вводе. Ввод панорамирования, вращения, зума, рамки и кликов при этом
не обрабатывается. Первый выбор остаётся selection-only, повтор включает
follow, смена цели отцепляет прежнее слежение. Правило закреплено в §123.1.

Во время проверки создания настоящего `CharacterPanel` также обнаружено
запрещённое Unity создание `VisualElement` в инициализаторе поля
`CharacterPanel.HtmlInventory`. Scratch-элемент теперь создаётся при первом
построении статистики предмета, на UI-пути, без подавления исключения.

  тест падает на невыполненном Follow. После проверки исправленный файл
  восстановлен; финальные пять тестов прошли на нём.
- Chrome 155, настоящий `roster.js`: два отдельных клика отправляют две
  команды `roster.select`; Shift передаёт `add:true`; перетаскивание нажатия
