# Игровой баг-репортёр (§114.8)

Любой игрок нажимает отдельный микрофон на основном HUD и сразу надиктовывает
ошибку. Как в First Signal, видны только микрофон, реагирующая на речь волна,
таймер, «Отмена» и «Готово». Превью скриншота и редактора текста перед записью
нет. «Готово» закрывает запись и возвращает игрока в игру немедленно.
Микрофон админа перенесён в DEBUG. Микрофон включается только по кнопке;
потеря фокуса прерывает запись. Предел записи — 90 секунд. Native использует
FMOD, браузер — getUserMedia/AudioWorklet с тихим выходом, без обратной связи.
Позднее разрешение микрофона после отмены сразу освобождает полученный stream.

Кадр игрового холста снимается до открытия формы. В WebGL HTML-окна в PNG
не входят: их названия сохраняются в контексте. Контекст берётся из доступного
клиенту снимка мира: версия, мир, tick/seed, камера, выбранный NPC, его цель,
план, движение, потребности, вещи, известные объекты, ближайшие персонажи,
мобы и объекты, ограниченный список диагностических событий. Это не дамп
сервера: неизвестное клиенту состояние, аккаунты, ключи и диалоги не включаются.

До восьми отчётов (32 MiB суммарно)
хранятся в очереди текущего сеанса. Распознавание и доставка идут по одному,
независимо от паузы игры. Сетевая ошибка повторяется через 4 и 15 секунд;
на HUD вращается индикатор обработки с числом ожидающих и растёт число
отправленных за сеанс. Подтверждённая сервером отправка показывает зелёное
«OK · Баг отправлен». Маленькая ошибка рядом с микрофоном нажатием сразу
повторяет первую неудачную запись. При повторе
сохраняются исходные контекст, PNG и requestId. Очередь не переживает закрытие
приложения или перезагрузку страницы.

## Подготовка сборки

`HexLiveBugReporterBuild.Prepare` читает приватный файл
`~/.config/hexlive/reporting.json` с полями `api`, `project`, `token`.
Здесь используется отдельная игровая capability Flashback: project=hexlive,
isAdmin=false, allowedStatuses=[created]. Это не ключ устройства/агента.
Подлинные права проверяются через `/api/auth/me` перед каждой сборкой.
Сгенерированный Resource с игровой capability исключён из Git. Менеджер
отчётов продолжает требовать отдельного права bugs.read.

## Проверка опубликованной веб-игры и Flashback

Проверка без `Origin` не подтверждает работу браузера. Перед публикацией и
после изменения конфигурации Flashback выполнить из корня проекта:

```sh
python Tools/check_bug_reporter_origins.py
```

Скрипт использует только приватную игровую capability из `reporting.json`;
ключ агента не подходит. Для обоих адресов игры он проверяет права,
браузерный preflight, приём WAV и JSON до валидации содержимого, запрет чтения
чужих отчётов и сохранение запрета для постороннего origin. Отчёты не создаются.
`--origin https://…` выбирает конкретный адрес. Опция `--wav <synthetic.wav>`
дополнительно проверяет настоящее распознавание: нужен синтетический mono
PCM16/16кГц WAV, создаётся только временный transcription draft, без бага.
Не использовать для этой проверки личные записи игрока.

Flashback должен разрешать точные origin (без `/play/` и завершающего слеша):

- `https://flashback.62-146-235-120.sslip.io` — собственный интерфейс;
- `https://play.62-146-235-120.sslip.io` — игра Singapore;
- `https://163-245-204-96.sslip.io` — игра New York.

Шаблон конфигурации — `Tools/flashback-hexlive-origins.compose.yaml`.
В Singapore он установлен как
`/opt/flashback/config/hexlive-origins.compose.yaml`, отдельно от неизменяемого
release. При последующем разрешённом развёртывании Flashback включать его
вторым `-f` после production `deploy/compose.yaml`, сохраняя проект `flashback`,
`--env-file /opt/flashback/.env` и явно выбранный тег образа. Перезапускать
только `app` через `up --detach --no-deps --no-build --pull never app`.
Простой restart контейнера не обновляет environment. Не заменять allowlist
на `*` и не отключать проверку Origin или Bearer.

**Rework #616, 09.11.2026.** Реальный запрос с Singapore получал HTTP 403
«Источник запроса не разрешён»: `ALLOWED_ORIGINS` отсутствовал, а fallback
содержал только собственный `PUBLIC_ORIGIN` Flashback. Поэтому WAV не попадал
в очередь; повтор из того же браузера тоже отклонялся. Применён указанный
override; пересоздан только `flashback-app-1`, образ
`cc2d611a4456b253f84a234d5b2ade8fcafb6fec` и контейнер PostgreSQL сохранены.
Проверки обоих игровых origin прошли; синтетическая русская запись реально
распознана (70 символов). Тестовые баги не создавались. Для применения
исправления достаточно повторить неудачную отправку в открытой игре:
перезагрузка потеряет очередь, которая хранится в памяти сеанса.

## Проверки реализации, 2026-11-09

- 15 NUnit-проверок: очередь, пределы памяти, резерв до записи, повторы,
  счётчик подтверждённых отправок, стабильный requestId,
  ограничение/копирование контекста, исключение речи и секретных полей,
  проверка прав capability, PCM и удаление длинных пауз.
- Полная симуляция: 2057 PASS, 6 существующих пропусков. Строгая WebGL-компиляция:
  0 ошибок / 0 запрещённых API. JS-проверки синтетического PCM: отмена ожидания
  разрешения, отказ, освобождение устройств, stereo→mono, WAV→WASM heap,
  жёсткий предел 90 секунд. Физический микрофон в этих проверках не используется.
- Настоящий браузер: исходный AudioWorklet записал поток от синтетического
  осциллятора, WAV содержал 440 Гц при 48 кГц, RMS 0,14; все tracks завершились.
  Проверка не запрашивала разрешение физического микрофона.
- Реальный Unity 6000.4.6f1 через официальный Unity CLI: компиляция и Prepare
  завершились с кодом 0.
- Настоящий Flashback: синтетический русский WAV распознан за 16,86 секунды;
  попытка чтения отчётов игровым ключом отклонена. Тестовый баг не создавался,
  микрофон пользователя не включался.
- Браузерная проверка настоящего HTML-компонента с имитатором транспорта:
  запись/Готово, немедленное открытие следующего отчёта, несколько записей
  очереди, просмотр неудачного отчёта, Ctrl+Enter, русский/английский,
  ширина 390 px и обычное окно. Проверка компонента не заменяет приёмку
  готового Player с настоящим микрофоном.

Образец поведения — First Signal main `7901ccdf2`: очередь и разделение
игрового ключа от управляющего; транспорт и обе формы адаптированы к HexLive.
