## 1. Серверный агент и Agent Studio (Codex)

- Studio — Avalonia-оболочка; логика в `Server/HexLive.AgentCore` (компилирует исходники `AgentHost`, без Unity). Поток: `/watch` → inbox сервера → AgentHost по `/mcp` → память → LLM → решение → команды/память/отношения → TTS → сервер → клиент. AgentHost — исходящий MCP-клиент, своего API для браузера нет.
- Профиль: `profiles.json` в `LocalApplicationData/HexLive/AgentStudio` (`StudioConfigurationStore.cs`), workspace `workspaces/<guid>` (SOUL.md, USER.md, MEMORY.md, `.state/state.json`, архив JSONL). Создание не идемпотентно (новый GUID на повтор). GUID профиля ≠ `identity.id` памяти ≠ `worldId+npcId`.
- Характер: один стиль `masha-sharp-v1` (`DialogueStyles.cs:43-46` бросает на любой другой) + общий шаблон `soul.md`. Каталога шаблонов нет. Общие правила (`Prompts/rules.md`) — редактируемые файлы, не версионированная политика.
- LLM: OpenAI/Grok/Claude/DeepSeek/Codex; ответы **не потоковые**. «Luna» в коде не найдена. Секреты — Keychain/Credential Manager (Linux-реализации нет) или env.
- Голос: ElevenLabs только TTS `/v1/text-to-speech/{voiceId}` → весь PCM → WAV → загрузка чанками по 128 KiB. Conversational AI не подключён. Голоса персонажей в `_ArtSource/Voice/voices.json` и голос профиля Studio — два разных источника.
- Действия: whitelist (`AgentProviders.cs:25`), `npcId` подставляется из привязки, исполнение через штатную шину. Действие стартует **до** TTS, но реплика генерируется **до результата** действия.
- Автономия: уход игрока платную автономию не останавливает — она живёт, пока мир не на паузе. Одна реплика может дать до 7 LLM-раундов (recall, справки, исправление плана).

## 2. Голос и команды на стороне игры

- STT: сервер выдаёт JWT Deepgram на 60 с (`DeepgramTokenBroker.cs`, 4/мин на владельца), `SttAvailable` в handshake только для соединения с player-token. Клиент шлёт целый WAV на `api.deepgram.com/v1/listen?model=nova-3&language=ru` (`DeepgramSpeechTranscriber.cs:24-39`).
- WebGL: нет ветки `UNITY_WEBGL` у транскрайбера, нет `.jslib getUserMedia`, `FmodMicrophoneCapture` без веб-пути, `Task.Run`/запись файлов в проигрывании ответа агента (`CharacterPanel.AgentVoice.cs:519-552`) — в вебе не работают (§168).
- Команды: единая точка `WorldHost.SubmitManualCommand` → `ManualCommandExecutor` (вердикт `ManualCommandAdmission`); у зрителя шина §121.9 с `correlationId`, 10 команд/с; MCP-набор: `move_to`, `interact`, `craft_item`, `talk_to`, `attack_*`, `aid_person`, `manage_inventory`, указания §167 и др. Таксономия отказов — ~70 строковых кодов без enum.
- Идемпотентность: `execute_agent_command(npcId, sequence, commandId, …)` с журналом в мире (`WorldHost.AgentCommands.cs`); одиночные `action` идут мимо него.
- Игроки: `hexlive-player.txt` — один токен на всех; `playerId` = GUID клиента из PlayerPrefs; назначения в `players.json` (`PlayerCharacterAssignments.cs`). В мире с `CreationConfig` управляет только `CreatorPlayerId`, остальные — зрители.
- Отношения в симуляции: только NPC↔NPC (`SocialState.Relationships`: Trust/Familiarity/Affinity/Authority). Отношение «игрок/агент ↔ NPC» на сервере — лишь транзитный `relationView` (≤1024 символа).

## 3. Стартовый мир и создание героя

- 6 лагерей уже в HugeIsland/Maniac/Islands (`PrototypeWorldDefinitionFactory.BigIsland.cs`, `HugeCampCount=6`). `WorldCreationConfig` (§162) задаёт лагеря и персонажей; `WorldLibrary` хранит миры в `worlds/<id>/`.
- `WorldCreationConfig.cs:197`: мир **без управляемого персонажа не проходит валидацию** (`noControlledCharacter`). Модель «один `PlayerCamp`, один создатель» несовместима с многими игроками.
- Автоспавн:

| Правило | Выключатель |
|---|---|
| Раненая потерпевшая id=900 (`ShipwreckSurvivorSystem`, день 3–5, Huge/Maniac) | **нет**, только проверка режима |
| Недельные прибытия §132 (`ColonyArrivalSystem`) | `Camp.ArrivalIntervalDays=0` / `ColonyArrivalIntervalDays=0` |
| Потерпевшая Islands §157.5 | тот же интервал |
| Волны чужаков §72.14, Кшиштов id=101 | лагерь Outsiders off / `Spec72.Enabled` |
| Ночной рейд стаи §46 | `RaidChancePerDay` — **во всех режимах** |
| Пресеты Маша 901 / Ника 902 | не передавать `--companion`/`--character-preset` |
| Подарок прибоя §63 (одежда, не NPC) | `SurfGiftIntervalDays`; одевает только женщин |

- Внешность: тела Marta (Ж) и Kshishtof (М) в People primal-v1; пол выводится из меша (`NpcState.Sex`), отдельного поля нет. Мужчина пока лысый (§169.3); цвет глаз в People не применяется (§169.5).
- Характеристики: 7 атрибутов + 9 навыков; бросок — нулевая сумма вокруг 0.6±0.4; валидация конфига **без бюджета** (только 0..1).
- Бельё: Ж — `underwear.briefs_primal` + `clothing.top_primal`; М — `underwear.briefs_primal_male`. Сейчас старт дополнительно даёт рюкзак и бутылку (в Islands ещё 5 бинтов).
- Черты §126 — битовая маска; шаблонов личности нет.
- Появление при входе отсутствует: игроку назначают существующего NPC. Переиспользуемо: `ColonyArrivalSystem.CreateArrival` + `PopulationArrivalMath.TryPickLanding`.

## 4. Крафт

- `RecipeCatalog`: словарь **`GoalType → Recipe`**; новый рецепт требует enum `GoalType`, запись в `GoalCatalog` (гейт `GoalTypeCoverageGate`), `case` в `GrantCraftOutput` и кодовую запись — иначе `Override` молча игнорирует данные.
- simdata v5: 12 рецептов. Бинт = 2 `resource.herb_leaf` без станции; единственная одежда — `clothing.leather_pants` из 1 шкуры у костра (устаревший id, нет в primal-v1 → на WebGL вероятна ошибка «нет active record», не проверено).
- Конвейер: `CraftingOptions.Resolve` → атомарная оплата `CraftProjectMath.CreateProject` → проект §61 → выдача; отмена возвращает ингредиенты. Идемпотентности по запросу нет (повтор после завершения = ещё одна вещь, по §138.5).
- Материалы рано доступны: ткань (4 волокна юки), верёвка (1 волокно), листья (`herb_leaf`, `palm_leaf`), шкура — нужен убитый зверь и нож (`Butcher`).
- Одежда: `GarmentDefinition` без секции крафта; расцветка = отдельный id с `PrototypeId`. primal-v1: 78 вещей (21 прототип × 4–7 цветов, 6 рюкзаков по 9 слотов), `gameReady=false`; в simdata нет 40 из 78 id (все `_male` и `backpack_primal_*`).
- Станции: костёр (`BesideReach` ≈ 1.6 wu), верстак `station.workbench` — образец для «швейного места»; счёт стройки — жёсткий `switch` без полей для шкуры/ткани (`BuildingBootstrap.cs:1120-1160`); один проект на станцию.

## 5. Где черновик расходится с кодом

1. «Взять контракт профиля Agent Studio» — его нет в нужном виде: это конфиг агента к готовому NPC.

3. «Отношения — серверные, промптом не меняются» — сейчас они в workspace и правятся через `USER.md` (покрыто тестом).
4. «ElevenLabs ведёт разговор» — подключён только TTS.
5. «Стриминг как телефонный звонок» — STT/LLM/TTS все целыми кусками; 3 с тишины уже съедают весь предложенный p95.
6. «Агент сообщает результат, а не обещание» — реплика рождается до исполнения.
7. «Оплачиваемая сессия закрывается при уходе» — автономия идёт до паузы мира.
8. «Пустой мир — шаблоном» — валидация требует управляемого персонажа; раненую девушку шаблоном не выключить.
9. «Новые вещи через крафт» — primal-v1 не готов к игре и не в simdata; рецепты не масштабируются на десятки расцветок.
10. «GPT-Luna» — в коде не найдена; доступность не проверена.

## 6. Что нужно решить Толе (уточнённые вопросы)

1. **Голос: A или B.** Код готов к B (свой оркестратор). A (ElevenLabs Conversational AI) — новая интеграция, но даёт стриминг/перебивание «из коробки». Предлагаю прототип на одной сессии с замером.
2. **Аккаунты.** Строим вход игрока на `HexLive.Identity` (сейчас ключи/permissions, без регистрации) или нужен внешний логин?
3. **Один герой на аккаунт** или несколько? Поведение при выходе: тело остаётся в мире, засыпает, исчезает?
4. **Автономия без игрока**: агент думает (и тратит деньги), когда игрок офлайн, или замирает?
5. **Отношения**: стороны — «агент-персонаж ↔ авторизованный игрок» и/или «↔ NPC»? Влияет ли доверие технически на допуск действий или только на тон?
6. **Пустой остров**: только без NPC или ещё без ночных рейдов стаи и волков?
7. **Стартовый набор**: только бельё, или рюкзак + бутылка тоже остаются (сейчас выдаются)?
8. **Бюджет навыков**: держать инвариант суммы атрибутов 7×0.6 и отдельный бюджет навыкам?
9. **Расцветки в крафте**: один рецепт + выбор цвета (из чего — пигмент?) или рецепт на каждую расцветку?
10. **Шкура** требует охоты и ножа — нормально для обуви/рюкзака или нужен альтернативный путь?

## 7. Предлагаемый порядок работ (после решений выше)

1. **Голосовой прототип** (решает A/B): одна сессия WebGL → STT → LLM → действие → TTS с замерами p50/p95 и стоимости.
2. **Фундамент без UI** (параллельно): идемпотентный `CraftItem(outputId)` вместо `GoalType`-на-рецепт; выключатель для `ShipwreckSurvivorSystem` и шаблон «пустой остров»; снятие `noControlledCharacter` для шаблона с ростером на входе; серверная проверка бюджета атрибутов.
3. **Серверный профиль + аккаунт**: Identity → `CharacterProfile` → спавн в лагере в идущем мире → `players.json`; идемпотентное создание.
4. **Серверный агент**: supervisor над `AgentCore`, серверные секреты, перенос отношений под сервер (запрет правки метрик), каталог характеров, «результат → реплика».
5. **Usage ledger**: журнал всех запросов провайдеров (включая ошибки/повторы), тарифы, лимиты.
6. **WebGL UI**: редактор героя, выбор лагеря, голосовой режим.
7. **Крафт primal-v1**: simdata ← People-каталог, секция крафта в одежде, бинт из ткани+листьев, обувь/рюкзак, затем «швейное место».
