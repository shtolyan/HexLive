# Закрытое тестирование: единый ключ (§166)

## Текущий цикл

Фаза 1: Windows Player и только Сингапур. Нью-Йорк отключён в меню и не
опрашивается. Production пока не обновлён; завершённая сборка и реальные
проверки доступа фиксируются отдельно в отчёте фазы.
Фаза 2 начинается после подтверждения игроком первой фазы: повысить протокол,
собрать и опубликовать новую версию, оставить старый клиент у игрока и проверить
экран «Обновить / Выход», установку и повторный вход.

## Компоненты

- Authority: отдельный `HexLive.Identity`, origin `127.0.0.1:5130`, публичный
  `https://keys.62-146-235-120.sslip.io/`. Вход в админку по тому же ключу.
- Игровой сервер: `HEXLIVE_IDENTITY_URL` включает обязательную проверку ключа и
  полномочий. Подставленный клиентом accountId не используется.
- Flashback: отдельное обновление приложения подключает ту же authority;
  существующие device keys автоматизаций сохраняются на переходный период.
- Windows: ключ сохраняется DPAPI, меню показывает Сингапур и отключённый Нью-Йорк.
- Права: `game.play`, `bugs.create`, `bugs.read`, `bugs.manage`, `server.admin`,
  `keys.manage`. Флажки меняются без перевыпуска ключа; операции проверяют
  актуальные права. Отзыв игры прекращает соединение за 60 секунд + timeout.

## Развёртывание первой фазы

1. Зафиксировать только изменения задачи и подготовить чистый checkout точного
   SHA по `CLAUDE.md`. Выполнить полные server/simulation suites. Сторонние dirty
   изменения основного рабочего дерева в релиз не включать.
2. Сохранить резервные копии миров, players.json, конфигурации systemd/Caddy,
   текущих release symlinks и базы Flashback. Не менять seed, mode, пути сейвов,
   существующие персонажи и обязательные EnvironmentFiles игрового сервера.
3. Развернуть self-contained identity в `/opt/hexlive-identity/releases/<sha>`,
   persistent data `/var/lib/hexlive-identity` с владельцем hexlive и mode 0700.
   Установить `Server/hexlive-identity.service`. Проверить отдельный Caddy site
   из `Server/Caddyfile.identity`, сохранив остальные сайты, затем reload.
4. Только в пустом реестре выполнить `--bootstrap-owner`, задав приватный
   `HEXLIVE_BOOTSTRAP_OUTPUT`. Не выводить ключ в журнал или репозиторий.
   Для подтверждённого Windows-профиля владельца задать
   `HEXLIVE_BOOTSTRAP_ACCOUNT_ID=31abe676e0d04aea991796ab15ed64b5`:
   это сохраняет его существующие назначения NPC 901/902 в текущем мире.
   Другие старые id автоматически не присваивать новым тестировщикам.
5. Развернуть игру из проверенного SHA, настроить authority через systemd
   override. Сохранить режим `--start-paused` и проверить эффективный ExecStart.
6. Обновить только приложение Flashback, сохранив PostgreSQL/volume/порты.
   Миграция добавляет central_account_id; ключи центральных браузерных сессий
   хранятся только в памяти, после перезапуска нужен повторный вход.
7. Проверить TLS/health/status/compatibility, неверный ключ, права независимо,
   изменение прав в открытой сессии, подмену accountId, отзыв и замену ключа.
   Вход владельца должен вернуть прежние назначения; временные тестовые ключи
   не должны создавать новые игровые назначения.
8. Передать владельцу ключ приватным локальным файлом и открыть Windows Player.
   Проверить ввод, повторный запуск, подключение и выбранные права с игроком.

## Контент Windows

Runtime-модели загружаются через Asset API и проверяются по SHA. Недостающие
Windows-варианты блокируют готовность релиза. Добавлять только требуемые
StandaloneWindows64 payloads с теми же metadata, сохраняя текущие macOS variants
через `Tools/content.py publish-all --retain-current-variants`.
Исторические audio-записи runtime index не скачиваются: по §152.7 звук/FMOD
входит в Player StreamingAssets. Это не исключение для отсутствующих моделей.

## Обновления

Найденный рабочий путь реализации: HTTPS latest manifest Сингапура → ZIP →
проверка размера/SHA-256 → новая папка установки → атомарный install-state.
Google Drive к этому каналу не подключён; не считать загрузку с Drive проверенной.
До первой публикации `/api/releases/v1/windows/latest` возвращал 404.
`Tools/build_release_windows.py --release` собирает Player и автономный
`HexLiveUpdater.exe`, затем ZIP/manifest. `Tools/publish_windows_release.py`
публикует архив и публичный manifest без внутреннего bug snapshot.

Player проверяет `/api/client/v1/compatibility` включённых регионов до входа и
при подключении. В этой фазе включён только Сингапур. Несовместимость блокирует
вход экраном «Обновить / Выход»; handshake защищает смену протокола между запросами.
Невозможность связаться с сервером не считается несовпадением версии.
Updater ждёт завершения Player, требует совпадения протокола latest, проверяет
архив, устанавливает новую версию и запускает её. Старая версия сохраняется.
Ошибки сети/пакета не заменяют рабочую установку; HTTP Range проверяется.
Автоматический macOS updater не входит в этот Windows-цикл.

## Ограничения первого теста

Authority хранит атомарный JSON, поддерживает одного writer и fail-closed
проверку. Общий лимит validate — 120 запросов в минуту; рост числа клиентов
потребует отдельного расчёта нагрузки. Последнего владельца keys.manage нельзя
лишить этого права через формы. OAuth Google/Apple пока не реализован.
