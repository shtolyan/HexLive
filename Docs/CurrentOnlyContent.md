# Одна актуальная запись объекта

Решение игрока от 09.11.2026: сервер больше не архивирует прошлые версии
объектов. Восстановление старой модели — checkout нужных исходников из Git,
сборка нужных платформ и обычная новая публикация.

Сохраняются `type/id`, текущие варианты для платформ, SHA-256, размер,
attachments, атомарная запись и технические счётчики `revision` /
`registryRevision`. Эти счётчики защищают кэш и параллельные изменения;
они не дают доступ к прошлым данным. HTTP `/history` возвращает 410,
админка показывает только текущие варианты. Save format 87 и wire27 не меняются.

При публикации новый payload заменяет прежний для своей platform/profile.
Текущие варианты остальных платформ сохраняются. При изменении общей metadata
необходимо передать все текущие платформы: архив больше не подстраховывает
частичное семантическое обновление. Файл удаляется, когда на него больше не
ссылается ни одна текущая запись или транзакционный intent. Это относится и к
attachments. Retired-объекты сохраняют свой текущий payload для старых сейвов;
удалять такие ID только по факту отсутствия в новом authoring-каталоге нельзя.
CLI удаляет собственный staging после успешной публикации, чтобы транспортные
копии не превращались во второй архив. При отказе staging остаётся для разбора.

Клиент и bundles для этой серверной смены формата не пересобираются. После
последующих публикаций старые SHA больше не обслуживаются; уже загруженные
объекты остаются в памяти/кэше клиента. Долгая сессия, которая ещё не скачала
заменённый payload, должна обновить реестр или переподключиться.

## Миграция существующего хранилища

Обычный запуск нового сервера отказывается обслуживать непереведённую историю.
Мигратор запускается отдельно, не создаёт мир и не делает игровых тиков.

```sh
python Tools/content.py compact --asset-root /path/to/candidate-assets --server-dll /path/to/new/HexLive.Server
python Tools/content.py compact --asset-root /path/to/candidate-assets --server-dll /path/to/new/HexLive.Server --apply
```

Первая команда только проверяет и показывает план. Вторая применяет его под
штатной блокировкой публикации. Последний доступный вариант каждой платформы
переносится из старой истории в единственную текущую запись. Отличавшаяся
платформенная metadata хранится при этом варианте; прежние записи и запасные
payload для него не сохраняются. До изменений проверяются SHA и размеры всех
сохраняемых файлов. Затем удаляются history и недостижимые blobs. Повторный
запуск ничего дополнительно не переносит и не возрождает удалённые ID.

Для production сначала делают отдельную candidate-копию records/history/changes
и hardlinks blobs. Её переводят новым бинарником и сравнивают с API-снимком
работающего старого сервера: все object ID, состояния, metadata, SHA/размеры,
icons и attachments, платформенные пробелы и legacy-resolve. Меняться могут
только технические счётчики. До подтверждённого совпадения active root не меняют.
Переключение сервера — отдельная авторизованная операция с остановленным
сохранением и проверкой прежнего мира после запуска. Старые publish-процессы
тоже должны перейти на новый бинарник, иначе они снова начнут писать history.

После успешной проверки актуального хранилища старые asset-root snapshots
удаляются в рамках разрешённого удаления истории: оставленные hardlinks старого
каталога иначе продолжат занимать место. Перед удалением проверяют точные пути
и ссылки всех сервисов. Восстановление модели после этой очистки требует
пересборки из Git; готового старого bundle на сервере уже нет. Резервные копии
миров и аккаунтов к истории моделей не относятся и сохраняются отдельно.

## Production, 09.11.2026

По отдельной прямой команде игрока Singapore и New York переключены на сервер
`053fb723be0a740e5f393e44a334c2426a636366` и проверенные каталоги без истории.
Player `811056cca`, wire27 и save87 сохранены. По одному stop/start игры на
хост; перед ним проверен полный остановленный backup миров, аккаунтов и
конфигурации. Бывшие active и rollback asset roots удалены только после
публичной проверки всех текущих WebGL payload и полного совпадения metadata /
SHA всех доступных платформ. Прежние нативные варианты Нью-Йорка теперь
разрешаются из текущих записей, без history fallback. Механика и назначения
персонажей не менялись; отдельное Apply каталога к существующим мирам не делали.
