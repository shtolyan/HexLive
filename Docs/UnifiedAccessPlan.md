# Единый ключ и изменяемые права — план внедрения

Уточнение игрока от 2026-09-19 к §166. Реализация находится на проверке:
центральный реестр с правами, вход админки по ключу, игровые проверки и
Flashback consumer добавлены. Существующие ключи автоматизаций Flashback
сохраняются на переходный период. Production ещё не обновлён.

Текущий цикл ограничен Сингапуром. Нью-Йорк не опрашивается и не изменяется;
включение региона — только по отдельной команде игрока. После первой фазы
(доступ и права) игрок подтверждает переход ко второй (старый Windows Player
против нового протокола и опубликованного обновления).

## Целевой контракт

Один ключ удостоверяет один аккаунт на обоих игровых серверах, в веб-админке,
админском режиме игры и Flashback. Никакого отдельного пользовательского
admin password, bug-token или admin-device-secret. Внутренний `accountId`
остаётся несекретной постоянной ссылкой на владельца персонажей и действий;
клиент не выбирает его самостоятельно.

| Право | Разрешённые действия |
|---|---|
| `game.play` | Играть на официальных серверах от своего аккаунта |
| `bugs.create` | Заносить новые баги |
| `bugs.read` | Просматривать список и карточки багов |
| `bugs.manage` | Редактировать и модерировать отчёты по правилам Flashback |
| `server.admin` | Пользоваться веб-админкой игровых серверов и admin-командами игры |
| `keys.manage` | Выдавать, заменять, отзывать ключи и изменять права аккаунтов |

Права независимы. Возможность играть не даёт отправку багов; отправка багов
не даёт модерацию; игровая админка не даёт управление ключами. Пресеты только
заполняют флажки, проверка всегда по конкретным правам. Например, тестировщик
получает `game.play` + `bugs.create`, остальные возможности выдаются явно.
Первоначально игровые права общие для обоих официальных серверов; формат
должен допускать будущую область действия `serverId` без смены ключей.

## Реестр и правила

- Аккаунт хранит имя, состояние, `permissions`, `revision`. Случайный ключ
  хранится только как hash и ссылается на accountId. Права не зашиваются в ключ.
- В админке — флажки прав при выдаче и редактировании. Можно расширить/урезать
  права без смены ключа, установки клиента и потери назначенных персонажей.
  Замена ключа сохраняет аккаунт и права; прежний ключ становится недействительным.
- Изменение требует `expectedRevision`; неизвестные права отклоняются, пустой
  набор допустим. Журнал хранит автора, время, набор до/после, выдачу и отзыв,
  но не полные ключи или заголовки авторизации.
- Последнего активного владельца `keys.manage` нельзя случайно лишить доступа
  веб-формой. Первый ключ владельца выдаётся безопасным локальным bootstrap;
  аварийное восстановление выполняется локально оператором authority.
  Постоянного второго пароля/обходного ключа в пользовательском входе нет.
- API проверки возвращает `accountId`, `permissions`, `revision`. Неверный ключ
  — 401; действующий ключ без нужного права — 403. Сбой authority не разрешает действие.
- Активная игра перепроверяет `game.play` не реже раза в 60 секунд. Админские
  действия и изменение прав проверяются непосредственно перед выполнением,
  включая отложенные команды и подтверждения. Снятое право не сохраняется
  в открытой панели/старой сессии. Выдача права работает с тем же ключом.
- Веб-сессия после входа по ключу — короткая, защищённая cookie с CSRF;
  это механизм браузера, а не второй пользовательский ключ. При отзыве ключа
  или прав следующие операции этой сессии запрещаются.
- Скрытие UI только улучшает интерфейс: все запреты повторяет сервер.

## Flashback — обязательное изменение отдельного сервиса

Исходников `shtolyan/flashback` в текущем checkout нет. Он должен принимать
центральные ключи и проверять `bugs.*` на каждом API-маршруте. Замена только
`BugReportStore.CurrentToken()` не реализует единую авторизацию.

Форма создания должна работать с `bugs.create` без предварительного чтения
всей очереди. Автор определяется по accountId на сервере. Прямые HTTP-запросы
без права отклоняются. Не передавать в Player общий сервисный/административный
ключ Flashback и не подменять ограниченный ключ игрока привилегированным.

Сохранить ограничения workflow агентов: право создавать/обрабатывать отчёты
само по себе не даёт подтверждать `fixed`, архивировать и удалять. Проверяются
и разрешённая операция, и тип субъекта. Автоматизациям выдаются собственные
аккаунты центрального реестра с минимальными правами, а не копия ключа игрока.

## Порядок реализации

1. **Authority:** расширить `KeyStore` и API, добавить ревизии, аудит,
   редактирование флажков, вход по ключу и bootstrap владельца. Заменить
   первоначальный логин/пароль админки authority.
2. **Игровые серверы:** `IdentityClient` + `/watch` проверяют `game.play`;
   `AdminEndpoints`, `WorldCreationEndpoints`, admin MCP и `GodMode` проверяют
   `server.admin`. В режиме authority старые пароль, общий токен и device grant
   не должны оставаться альтернативным входом.
3. **Flashback:** внедрить центральную identity и карту прав всех маршрутов;
   подготовить миграцию существующих player/agent/admin ключей.
4. **Player:** получать актуальные права; `AdminVoicePanel` больше не создаёт
   отдельный секрет; `BugReportStore` использует единый ключ. Разделить создание
   багов и чтение/модерацию очереди. Обновлять UI при изменении прав.
5. **Миграция:** сначала authority и потребители, затем Player. Проверить новый
   ключ владельца на всех сервисах до отключения старых способов входа.
   Не удалять существующие серверные учётки/сейвы и не отзывать ключи рабочих
   автоматизаций до проверки замены.
6. **Релиз:** административный SSH-доступ, развёртывание двух серверов и
   Flashback, сквозной тест Player, восстановленный канал обновлений.

## Критерии готовности

- Один ключ выполняет все выданные действия на обоих серверах и в Flashback.
- Ключ только с `game.play` не создаёт баг и не выполняет admin-команду даже
  прямым HTTP/WS-запросом. `bugs.create` работает без доступа к чужим отчётам.
- Добавление права действует без перевыпуска ключа; снятие блокирует действие
  в уже открытой панели, а снятие `game.play` завершает активную игру в пределах
  60 секунд плюс ограниченный timeout authority.
- Отзыв прекращает все пользовательские доступы. Замена ключа возвращает
  прежних персонажей без расширения прав.
- Проверены подмена accountId, самостоятельное повышение прав, legacy bypass,
  устаревшее подтверждение команды, конфликт ревизий, CSRF, недоступность
  authority, перезапуск и защита последнего владельца `keys.manage`.
