# Позиционирование и повороты — что сломано по сути (задание на рефакторинг)

Документ написан по итогам дня отладки «скользит / крутится / проваливается в
пол» (§109.10–109.14). Все числа — замеры на живом сейве игрока и на
прототипном острове, не оценки. Задача передаётся отдельному агенту: здесь
диагноз и предлагаемая форма решения, без готового патча.

---

## 0. Корень всего: у тела ТРИ независимых представления

| Что | Кто владеет | Кто читает |
|---|---|---|
| `Position` (Float2, XZ) | ~9 систем (см. §1) | вид (XZ трансформа), дистанции, бой |
| `CurrentJunction` | MovementSystem, PerceptionSystem, постройка | пути, досягаемость, занятость |
| `Tile` | MovementSystem (на переходе), пара спец-мест | **высота пола в виде**, погода, вода, соседи |

Они синхронизируются «по договорённости», а не по построению. Любая система,
которая двигает `Position`, обязана помнить про две другие — и половина систем
не помнит. Отсюда весь класс визуальных багов:

- **двинули Position, не тронув Tile** → вид рисует тело на высоте СТАРОГО
  тайла: «боевая стойка вбивает в пол» (сосед выше) или «висит в воздухе»
  (сосед ниже);
- **двинули Position, не тронув Junction** → досягаемость и занятость считают
  тело в одном месте, а игрок видит в другом;
- **перепрыгнули Tile, не двинув Position** (обратный случай, §21.21B) →
  телепорт на кадре.

Замер (сейв игрока, 4000 тиков, 4 NPC): **1914 тиков** тело СТОИТ (не идёт, не
прыгает) дальше вписанной окружности своего гекса; максимум ухода — **2.02 wu**
при вписанной **1.30**. Смена тайла у стоящего — 28 раз, из них **9 со сменой
высоты**: это ровно те кадры, где вид дёргает тело по вертикали.

## 1. Все писатели `NPCState.Position` (аудит)

| Место | Когда | Двигает без ходьбы | Есть предел |
|---|---|---|---|
| `MovementSystem:866` | обычный шаг | нет (`IsMoving=true`) | шаг за тик |
| `MovementSystem:827` | приход на узел (снап) | да, 1 тик | ≤ шага |
| `MovementSystem:788` | взлёт прыжка (снап на HopFrom) | да, 1 тик | ≤ шага |
| `MovementSystem:116/137` | окно прыжка (полёт) | **да, при `IsMoving=false`** | отрезок HopFrom→HopTo |
| `HumanCombatSystem.HoldStandOff` | отжим стойки, каждый быстрый тик | **да** | §109.11+ (см. ниже) |
| `ExecutionSystem:1850/1858` | лечь (центр гекса / место шеренги §113) | да | габарит гекса |
| `ExecutionSystem:1937` | сесть/стирать (`PlaceAtEdge`) | да | фиксированный узел |
| `MobSystem:1298` | смерть — тело к якорю | да | — |
| `WorldSaveSerializer` / `WorldSnapshotCodec` | загрузка / сеть | — | — |

**Ни один из них не обновляет `Tile`.** Обновляет только MovementSystem, и
только на переходе между тайлами.

## 2. Повороты: у тела ЧЕТЫРЕ прицела, и они спорят

| Кто целится | Куда | Слой |
|---|---|---|
| `MovementSystem` (ходьба) | следующий узел пути — **или точка взлёта прыжка**, если впереди стена (§21.21B v9 «ONE TARGET») | Fast |
| `MovementSystem` (взлёт) | направление прыжка HopFrom→HopTo | Fast |
| `MovementSystem` (посадка) | ⛔ был доворот в узел пути — **снят в §109.13**, спорил с ходьбой | Fast |
| `HumanCombatSystem.FaceOpponent` | противник | Fast (⛔ теперь только когда стоит, §109.13) |
| `RaidSystem.BraceMarks` | подходящий обидчик | Medium (мёртвая зона 35°, §109.13) |
| `ExecutionSystem` ×4 | объект работы / место сна / кромка воды | Fast |

Замер до правок (сейв игрока, первый забег): доворот при посадке целился в
узел под ногами (68°), ходьба на следующем тике — в точку взлёта (20°). Тело
**три тика доворачивалось в никуда (+45°) и рывком возвращалось (−24.7°)** —
это и есть «повернулся зачем-то лишний раз».

После снятия лишнего прицела: развороты 499 → 487 за 3000 тиков; при
ПОЛНОСТЬЮ выключенных боевых фичах — 560. То есть **основное верчение живёт в
самой ходьбе**, а не в бою:

- шаг бега **0.75 wu**, расстояние между узлами решётки **0.37 wu** — за тик
  тело проскакивает два узла;
- `PathIndex` двигается только по «прибытию», поэтому цель прицела то остаётся
  позади (угол разворачивается на 180°), то перескакивает вперёд;
- поворот ограничен `TurnSpeed × BaseTurnSpeedFactor × dt` = **54° за тик**
  (до 108° у ловких) — это 216–432°/с, то есть щелчок, а не поворот. Замерены
  единичные тики с `dRot = −108°`.

Из 487 разворотов **332** метрика классифицирует как «повернулся и почти сразу
обратно».

## 3. Вид усиливает любую ошибку симуляции

- `HexWorldRenderer.InterpolateViews`: `Vector3.Lerp(prev, curr, alpha)` за
  один тик (0.25 с). Скачок позиции = плавный проезд за 0.25 с. Ходьбы при
  этом нет (`Speed` в аниматоре считается по фактической дельте трансформа) →
  «скользит без шага».
- Высота: `ActorGroundY(npc.Tile)` — **от тайла**, не от фактической точки.
  Значит любое расхождение Position↔Tile мгновенно видно по вертикали.
- Защита от скачка есть только по Y (`ElevationStep × 0.5` → мгновенный снап +
  клип прыжка) и по «пропущенным тикам» (`PoseSnapTicks = 12`). По XZ защиты
  нет вовсе.
- ⛔ Пробовали лечить «не сглаживать скачок» — **откачено**: у прыжка взлёт и
  посадка законно ставятся рывком, и снап их ломает («перед прыжком
  телепортируется»). Лечить надо источник, а не сглаживание.

## 5. Предлагаемая форма решения (то, чего не хватает)

1. **Один владелец позиции.** Ввести `BodyMotion` (или расширить
   `MovementState`) — единственную точку, через которую МОЖНО двигать тело:
   `BodyMotion.MoveTo(world, npc, position, reason)`. Внутри — обязательная
   синхронизация `Tile`/`Junction` (или явный отказ, если новая точка вне
   допустимого), плюс трасса причины. Прямые присваивания `npc.Position = …`
   вне этого хелпера запретить гейтом (как `HardcodedIdLint`).
2. **Гейт «тело в своём тайле».** Тест на прототипном мире: у стоящего
   (`!IsMoving && HopTimer<=0`) расстояние до центра `npc.Tile` не превышает
   вписанной окружности. Сегодня он бы падал 1914 раз за прогон.
3. **Один прицел.** Ввести `Facing.Desired(world, npc)` — единственная
   функция, отвечающая «куда смотреть сейчас», с явным приоритетом: бой >
   прыжок > путь > работа. Все нынешние писатели `DesiredRotationDegrees`
   заменяются на неё. Гейт: за прогон не более N реверсов направления на
   NPC-день (метрика уже написана, см. §2).
4. **Прицел ходьбы по следующему НЕПРОЙДЕННОМУ узлу.** Причина «повернулся
   назад» — цель осталась позади после длинного шага. Нужен либо advance
   `PathIndex` по проекции на отрезок, либо look-ahead на N узлов вперёд с
   выбором первого, до которого ещё идти.
5. **Скорость поворота — как у походки.** 54–108° за тик это щелчок; поворот
   должен быть ограничен так, чтобы за тик не превышать ~30°, а «разворот на
   месте» оставаться отдельным состоянием (оно уже есть — `Rotating` +
   `TurnFreezeAngle`).

Порядок: (2) гейт → (1) владелец позиции → (4) прицел ходьбы → (3) один
прицел → (5) темп поворота. Первые два дают немедленный видимый эффект и
страхуют остальное.
