# Голосовой администратор (§161)

Изолированная реализация: `codex/voice-admin`, актуализирована до `c836a71f8`
из master. Микрофон использует общий `PlayerVoiceCaptureOverlay` и новый
FMOD-режим из §160: центральная карточка с уровнем звука, отправкой и отменой,
полный mute игры и завершение после 3 секунд тишины. Не подключать к production до
прохождения серверных тестов и проверки клиента из этой ветки.

Путь команды: FMOD → Deepgram → `/watch` → AdminAgentHub → отдельный Python
адаптер → Codex App Server → три разрешённых инструмента MCP → AdminCommandBus.
Python 3.10+ использует только стандартную библиотеку. Подтверждение удаления
идёт от игрового клиента; инструмента подтверждения у модели нет.

## Подготовка сервера

1. Собрать сервер и клиент из одной ветки. Для локальной сборки сначала закрыть
   Unity Editor — правило `CLAUDE.md` действует и на .NET тесты.
2. Использовать отдельный тестовый сервер с отдельным постоянным save-каталогом,
   player token, admin account и портом. Не указывать production save.
3. Включить обычный player control. Установить одинаковый случайный
   `HEXLIVE_ADMIN_AGENT_TOKEN` длиной не менее 32 символов в окружении сервера и
   адаптера. Это отдельный секрет, не player token и не API key OpenAI.
   Хранить env-файл с правами 0600; не коммитить его.
4. Для голоса настроить существующий DeepgramTokenBroker (§160). Текстовый ввод
   работает без STT. Deepgram тарифицируется отдельно от подписки Codex.
5. Создать отдельного непривилегированного OS-пользователя адаптера с пустым
   рабочим каталогом и собственным `CODEX_HOME`. Не давать ему доступ к сейвам,
   игровому репозиторию, SSH-ключам и окружению production. Не копировать
   личный Codex config, плагины, MCP-серверы или skills в этот профиль.

## Авторизация Codex по подписке

Под пользователем адаптера, с его собственным `CODEX_HOME`:

```sh
codex login --device-auth
```

Завершить вход в браузере своей учётной записью ChatGPT. Это ручной вход владельца;
пароль и одноразовый код не передавать в игровой чат. На сервере необходима версия
Codex CLI с experimental dynamic tools в App Server. Доступность Astra проверяется
через `model/list`; если её нет у этой учётной записи, адаптер останавливается.
Платный OpenAI API автоматически не подключается.

```sh
python3 /srv/hexlive-admin/admin_agent.py \
  --endpoint http://127.0.0.1:8080/mcp \
  --workspace /var/lib/hexlive-admin/workspace \
  --model gpt-6-astra --doctor
```

Порт заменить на порт тестового сервера. Для удалённого адреса требуется HTTPS.
`--doctor` проверяет MCP, вход ChatGPT и модель, но не делает запрос к модели и
не подтверждает доступность квоты. Убрать `--doctor` для постоянного процесса.
Каждый пользовательский запрос создаёт короткую ephemeral-сессию Codex. Ожидание
сообщений и heartbeat MCP не вызывают модель. При исчерпании лимита операции не
повторяются автоматически; смотреть фактический мир и журнал.

Официальные сведения: [App Server](https://developers.openai.com/codex/app-server),
[авторизация](https://developers.openai.com/codex/auth).

## Привязка и команды

Войти в существующую веб-админку, открыть `/admin/voice`, скопировать Client ID
из игровой панели «Админ», выдать код на пять минут и ввести его в клиенте.
Индивидуальный секрет хранится в Keychain (macOS) или DPAPI (Windows); другие
платформы пока не поддерживают сохранение секрета. Сервер хранит только хеш.
Отзыв на этой странице блокирует последующие команды, перепривязка меняет секрет.

Примеры: «Вылечи выбранную», «Верни ей левую ногу», «Поставь лучший протез правой
руки», «Восстанови все нужды», «Сделай силу 0.8», «Дай ей 3 доски».
Создание NPC и зданий требует явных координат Q/R.
[Схема штатной сетки](placement.svg): 37 внутренних и 24 граничных узла,
радиус гекса 1,5 wu, шаг узлов 0,375 wu. Поддерживаемые определения
модель получает из каталога. При неоднозначном имени или конечности требуется
уточнение. Для удаления показать точную цель и подтвердить отдельным «да» либо
кнопкой в течение 60 секунд. Изменившаяся цель требует нового запроса.

Последние 100 результатов: `/admin/voice/history`, только после веб-входа.
Журнал хранится в `admin-receipts` рядом с save, содержит команды и clientId,
без голосовых файлов и полных разговоров. `OutcomeUnknownInspectState` означает
незавершённую запись результата: не повторять автоматически, проверить мир.
Сохранённые подтверждения не переживают перезапуск и смену мира.

## Проверка перед запуском

Без Unity/.NET сборки можно выполнить:

```sh
python3 -m unittest discover -s Tests/Tools -p test_admin_agent.py -v
python3 Tools/spec_index.py --check
```

После закрытия Editor — тесты `AdminWorldCommandTests`, `AdminAccessTests`,
`AdminCommandBusTests`, `WorldHostCommandIngressTests` и общие simulation/server
проверки по `CLAUDE.md`. Затем открыть Unity именно из feature worktree, проверить
компиляцию, микрофон, повторное подключение, восстановление всех четырёх
конечностей/позы/протезов, отказ обычному клиенту и голосовое подтверждение.
Не считать Python-тесты проверкой работающего Unity-клиента или live Astra.
