# Маша: реализация и проверка характера

Дата проверки: 2026-09-09. Ветка: `master`, базовый commit `617837cbc`.
Отчёт фиксирует проверки локальных изменений до их commit/push.
Production rollout не выполнялся.

## Реализация

- `AgentPromptBuilder` — общий системный контекст для Studio и CLI, без дополнительного модельного переписывателя.
- `DialogueStyleId=masha-sharp-v1` — отдельный авторский профиль: конкретные подколы,
  естественный мат, самостоятельность, тёплая колкость при близости. Назначается
  только существующей авторской Маше, не новым персонажам по совпадению имени.
- Два детерминированно выбранных речевых эталона. Примеры — выдержки из одобренных
  сцен исходной задачи, без литературных ремарок; не воспоминания подключённой Маши.
- Обязательные отношения и игровое время не конкурируют с recall; отдельный бюджет
  воспоминаний 3200 символов. Авторский стиль не зависит от первых 720 символов SOUL.
- `relationshipAssessment` и существующий `VoiceRelationship`: доверие ±0.03,
  симпатия ±0.02, серьёзное отрицательное воздействие −0.06/−0.04. Знакомство +0.02
  только при значимом новом знании. Собственная грубая реплика не изменяет эти шкалы.
- Авторизованный senderId сервера, изоляция по серверному endpoint (включая путь) + speakerId внутри
  workspace профиля. Отдельно сохраняются численные отношения, прозвище/причина,
  user-факты, последние 12 строк разговора и обработанные messageId (окно 4096).
- Обработка последовательных пакетов одного отправителя; частично повторённый
  пакет очищается от уже обработанных сообщений до нового запроса. Сохранение
  результата и отношений проходит через существующий outbox.
- Архив schema 2, backup schema 1 перед миграцией, исходные числа/документы сохранены.
  Старое отношение получает только подтверждённый владелец; неизвестная принадлежность
  сохраняется отдельно и не выдаётся новому человеку. Старые неразмеченные личные
  записи не подмешиваются другому собеседнику.
- Время — реальные тики мира и серверный dayLengthTicks, а не прошедшее реальное
  время. Пауза = 0; смена мира/откат = неизвестно. Приоритет серверного worldId
  позволяет различать миры с одинаковым seed, в том числе в CLI.
- Речь до 600 символов, intent до 240; WAV до 60 секунд/6 МиБ, включая viseme baker;
  при ошибке TTS остаётся текст. Протокол v15 требует согласованных клиента и сервера.
- Studio показывает сохранённые отношения read-only; Unity получает отношение
  именно текущего авторизованного игрока, имя голоса и отрицательную симпатию.

Настроенная модель не менялась: Codex `gpt-5.6-terra`, reasoning `low`.
Рабочие числа отношений Маши не поднимались до тестовых максимумов. В конфигурации
Studio при открытии preview сохранён только новый выбранный профиль речи.
Агент оставлен остановленным; тесты не управляли живым миром.

## Реальная модель

Стенд: `Tools/HexLive.AgentDialogueEval`. Он использует настоящий prompt builder,
выбранную интеграцию, серверный каталог аргументов, синтетическое состояние и память.
Никаких MCP-действий, TTS, изменений живой Маши или скрытых рассуждений в отчёте.
30 комбинаций (5 отношений × 6 сцен) по 2 запуска; внутри режима — многоходовая история.
Это ограниченный набор сюжетов, не гарантия для всех игровых ситуаций.

Неудачи сохранены, не исключены из знаменателя:

- `1-slight-saved`: неизвестное значение emotion/reaction; валидатор отклонил весь ответ.
- `1-dislike-bluff`, `2-dislike-bluff`, `1-close-ocean`: недостаточно характерная речь.
- `2-affection-only-god`, `2-affection-only-machete`: слабое тепло при высокой симпатии.
- Четыре ocean-сцены: потенциально опасный совет ошибочно получил seriousHarm=true,
  хотя Маша отказалась и вред не был подтверждён. После анализа добавлено точное правило
  различать риск и причинённый вред; проверяется отдельным полным повтором.
- Есть некритичные неточности: приписывание игроку нахождения у костра, уверенные
  предположения о чужом знании/способности распознать блеф. Они отмечены в CSV отдельно.

Предшествующие прогоны сохранены в `Build/AgentDialogueEval/`: `masha-sharp-v1`,
`masha-sharp-v1-final`, `masha-sharp-v1-acceptance` (43 ответа, остановлен при уточнении
профиля, не считается полным). В ранних версиях повторялось заполнение пустого прозвища;
инструкция «оба поля null, если не переименовываешь» убрала эту проблему в последнем полном прогоне.

Окончательный повтор: `Build/AgentDialogueEval/masha-sharp-v1-release-check/`.

Это пограничная внутренняя оценка, а не гарантия качества и не разрешение
автоматического production rollout. Отдельно отмечены фактические неточности;
успех формы аргументов не приравнен к успеху игрового действия.

Шесть непрошедших строк:

- `1-slight-saved`: вновь неизвестное emotion/reaction; отклонённый ответ, не успех.
- `1-slight-bluff`, `2-slight-bluff`: разумные, но безличные отказы.
- `1-close-ocean`: тепло есть, колкости недостаточно.
- `2-affection-only-god`: недостаточно тепла при высокой симпатии.
- `2-affection-only-bluff`: при низком доверии решение слишком опирается на
  уверенность голоса. В первом запуске этой сцены была явная оговорка о проверке
  советов, поэтому он оценён иначе; обязательного запрета блефа при низком доверии нет.

Неудачные реплики не добавляются в авторские примеры. Сохраняются вариативные
пограничные случаи; критерий не требует слова «любимый» или мата в каждой строке.
Например, подкол «за “включи мозги” получишь счёт позже» может передавать близость
без прямого ласкового обращения. При другой человеческой оценке процент может отличаться.

После этого прогона профиль и prompt не менялись. Завершающие правки ядра относятся
к изоляции серверных endpoint и worldId; они проверяются отдельными тестами и не
входят в синтетический сценарный генератор. Исходные SHA-256 проверенного контекста:


SHA-256 ядра окончательного модельного стенда:
`302ad45294ec6141ccece1cbc92ec55011af688cf30bc2df06cc484227968427`.

Это разные бинарные сборки; совпадение четырёх исходников контекста выше проверено
после финальных тестов. Результат модельного стенда не выдаётся за запуск нового
бинарного пакета в живом мире.

## Сборки и UI

- Локальные пакеты: `Build/DialogueRelease/Server`, `Build/DialogueRelease/AgentHost`.
- Финальный preview Studio: `Build/AgentStudio/preview-20260908-181844/Agent Studio.app`.
  Это framework-dependent пакет для установленного .NET 9, не полностью автономный
  установщик и не заявление о завершении всех функций Agent Studio.
- Открытие предыдущего preview (`152700`) проверено: Маша, выбранная модель,
  `Stopped · no requests from Agent Studio`. Проверены AI · Mind и новый read-only
  просмотр Voice relationships: пустое состояние отображается корректно. Прежние
  отношения ещё не привязаны, так как живого сообщения подтверждённого владельца
  после миграции не было. Позже уточнён текст этого состояния, чтобы не создавать
  впечатление потери старых данных. Живые субтитры/озвучка не проверены.
- Первая клиентская сборка упала внутри нативной LMDB/обработчика crash Unity.
  Остановлен только собственный batch-процесс. Ничем не удерживаемая оставшаяся
  блокировка сохранена в `/private/tmp/hexlive-masha-unitylock-v0.1.101`.
  Стек: `/private/tmp/hexlive-masha-unity-sample.txt`.
- Вторая development-сборка скомпилировалась, но не опубликована: 1,777,884,040 bytes
  против допустимых 891,289,600 bytes (850 МиБ). Основной размер — отладочный
  GameAssembly (~1 ГиБ) и UnityPlayer (~251 МиБ). Гейт не ослаблялся.
- Штатная сборка `--release` без отладки успешно завершена: версия 0.1.101,
  протокол v15, `Build/DialogueRelease/PlayerReleases/v0.1.101/HexLive.app`.
  Размер приложения по Unity summary — 666,669,546 bytes (635.8 МиБ), ниже 850 МиБ;
  0 ошибок, 585 предупреждений, локальная ad-hoc подпись проверена сборочным скриптом.
  Полный build output с символами существенно больше самого приложения.
  Использован отдельный output-root: установленная рабочая игра и её обычный
  latest-link не заменены. Подробности — `BUILD_REPORT.md` и `unity-summary.json`
  рядом с приложением.

Production не обновлён. Перед rollout остаются живой разговор/озвучка с игроком
и согласованное обновление сервера и клиента до v15. Отдельные прежние
задачи Studio (Windows/native credentials, шифрование всех служебных записей,
полный импорт/экспорт) этим изменением не объявляются выполненными.
