## §145 Единая шина команд NPC (iteration 145)

Один и тот же приказ колонистке — клик игрока, LLM-пилот (§32.15), MCP-агент
(§144), игрок на удалённом клиенте — это ОДИН объект `ISimulationCommand` и
ОДИН валидатор `ManualCommandExecutor.Apply`. Каналы различаются только
доставкой и правом говорить; вторых правил и вторых исполнителей нет.

### §145.1 Четыре канала — один шов

| Канал | Доставка | Право говорить | Вердикт |
|---|---|---|---|
| Клик игрока (локально/loopback) | `SimulationCommandQueue` → дренаж в начале `Step()` | своё окно — свой мир | трасса `ManualOrderRejected` → тост |
| LLM-пилот §32.15 | `LlmCommandTranslator` → прямой `Apply` внутри тика | контур включён оператором | `ManualCommandAdmission` синхронно |
| MCP-агент §144 | HTTP `/mcp` → `WorldHost.SubmitManualCommand` | Bearer-токен + лиз | `ManualCommandAdmission` в ответе вызова |
| Игрок по сети (§145.3) | кадр `NpcCommand` → `SubmitManualCommand` | токен игрока + лиз | кадр `CommandResult` своему автору |

### §145.2 Кодек команд: забыть нельзя

`Simulation/Wire/SimulationCommandCodec.cs` — явная таблица «тип → номер →
writer → reader» для ВСЕХ `ISimulationCommand`. Номера append-only: это формат
провода, переиспользовать или менять их нельзя, новый тип получает max+1.

Покрытие держится не дисциплиной: `CommandCodecCoverageGate` находит рефлексией
все конкретные типы команд и требует (а) проштампованный образец, (б)
Write→Read→Write байт-в-байт с попарно разными значениями полей. Плюс
`-hexlive-loopback` пропускает КАЖДЫЙ приказ через encode→decode — забытая в
кодеке команда ловится нажатием Play, как забытое поле снапшота (§83.1).

⭐ Правило чек-листа: **новая `ISimulationCommand` ⇒ case в
`SimulationCommandCodec.Write` и `Read`** — гейт упадёт с именем типа.

Command wire v6 (#359) добавляет opcode 42 для `TalkToCommand` с запрошенной
темой. Старый opcode 11 и его байты остаются прежними для команды без темы;
новый reader принимает оба. Состояние темы в плане пишется в конце NPC-записи
save v73, старые версии читаются без запрошенной темы (§28.15G).

### §145.3 Игрок по сети (wire v5)

- **Кадры.** `NpcCommand = 10` (client→server: int32 correlationId + команда
  кодеком), `CommandResult = 11` (server→client: correlationId + вердикт
  `Accepted/Rejected + Actor + Order + Reason`). Рукопожатие v5 несёт
  `ControlEnabled` (токен принят — этому соединению можно приказывать) и
  `ControlOwner` (канонический owner, `ws:<guid>`).
- **Идентичность.** Токен игрока — `--control` на сервере →
  `hexlive-player.txt` рядом с сейвом (0600, печать один раз; форма — как
  токен MCP §144.1, общий `AccessTokenFile`). Клиент шлёт его заголовком
  `Authorization: Bearer …` НА HTTP-upgrade `/watch` (не в query string — там
  он тёк бы в логи) вместе со стабильным `X-HexLive-Client-Id` из PlayerPrefs:
  owner лиза переживает реконнект и перезапуск игры. С §149 тот же GUID
  является ключом постоянного назначения персонажей; сервер принимает его
  только в канонической форме GUID `N`, а текущий handshake v10 несёт
  добавленный в v9 `AssignedNpcIds`. Аргумент клиента —
  `-hexlive-token <значение|путь-к-файлу>`. Без токена соединение — прежний
  анонимный зритель, и весь ручной UI спрятан (`SupportsNpcCommands`).
  Игрок ≠ оператор: токен не даёт ни часов, ни админки — §83.2.10 не тронут.
- **Ingress на сервере** (`ViewerConnection`), порядок обороны: целость кадра
  (потолок 4 КБ; фрагментированное сообщение дочитывается и отвергается —
  иначе следующий Receive прочтёт его середину как новый кадр) → авторизация →
  token-bucket rate-limit (10/с, всплеск 30 — щедрее живого игрока, душит
  цикл) → разбор → реестр лиз → `SubmitManualCommand`. Сервер не верит клиенту
  ничего; «агент не может больше игрока» (§144.3) распространяется на игрока
  по сети буквально.
- **Вердикт.** Отказ едет `CommandResult` ТОЛЬКО автору; клиент синтезирует из
  него локальное событие `ManualOrderRejected` — существующий тост §121.5
  работает без правок UI. `ManualOrderRejected` в поток событий сервера не
  попадает НИКОГДА (у потока нет адресата). Асинхронный жизненный цикл —
  `ManualOrderInterrupted`, `ManualControlExpired`, `GroupOrderResult` — едет
  потоком: отдельный от летописи набор `GameEventTypes.ManualOrderReplies`
  (история колонии и звук их не видят), серверный фильтр — `IsWireRelevant`.
  Снятие ручного режима самим сервером клиент дополнительно ловит краем
  `IsManualControl` по снапшоту (тост `toast.manual_expired`).

### §145.4 Единый реестр лиз

`Server/ControlLeases.cs` — ОДИН словарь «npcId → владелец» на процесс, для
всех внешних контуров. Owner — строка с неймспейсом: `mcp:<session>`,
`ws:<clientGuid>`; коллизия контуров исключена синтаксически. Локальный игрок
в реестре не участвует — его мир принадлежит только ему.

- С §149 сетевой игрок сначала проходит постоянный
  `PlayerCommandAssignment`: каждый актор должен входить в его
  `AssignedNpcIds`, смешанная группа отклоняется целиком с `NotAssigned`.
  Только затем работает временный маппинг ниже. MCP постоянного назначения
  не имеет и сохраняет прежний прямой вход в реестр лиз.
- Маппинг команд: `SetManualControl(true)` → `TryAcquire` (идемпотентно для
  своего владельца), `(false)` → `Release`, обычный приказ → `TryRenew`.
  Управление одеждой и инвентарём (`SetOutfitLock`, `ManageInventory`,
  `TransferInventory`, `TransferContainer`) — намеренное исключение: после
  проверки постоянного назначения игрока оно доступно и в AI-, и в ручном
  режиме, не берёт и не продлевает manual-control lease. Чужой NPC всё равно
  отклоняется как `NotAssigned` до этого исключения.
  Групповые проверяются ПО КАЖДОМУ актору и отказывают целиком: `Apply` не
  возвращает пер-акторные вердикты, и смешанная группа исполнилась бы частично
  и молча.
- Таймаут лиза (120 с, `--mcp-lease`) МЕНЬШЕ §121.7 (300 с) намеренно: сначала
  владение возвращается в общий котёл, потом симуляция забирает колонистку.
  ⭐ Истечение больше не молчит: пары (npcId, owner) копятся
  (`CollectExpired`), и фоновый свип сервера обязан вернуть каждую брошенную
  под ИИ (`SetManualControlCommand(false)`) — раньше она висела в ручном
  режиме до §121.7 без владельца.
- У подключённого игрового клиента выделенная ручная колонистка обновляет свой
  лиз идемпотентным `SetManualControl(true)` каждые 2 секунды realtime. Поэтому
  игрок не остаётся с жёлтым маркером и `NoLease` после долгого выбора у двери;
  отключённый клиент или клиент без выделения heartbeat не шлёт и штатно
  освобождает колонистку по таймауту. Интервал ниже минимально допустимого
  `--mcp-lease=5`, не зависит от скорости/паузы мира и для группы обновляет
  только уже ручное подмножество.
- World-swap (`/admin` «новая колония») чистит реестр целиком (`Clear`);
  оператор может снять чужой лиз (`ForceRelease`) из админки.
- Отказ по лизу называет владельца (`ControlledByOther`), пустой реестр —
  `NoLease` («сначала возьмите управление»).

### §145.5 Композиционный корень (подключено)

`--control` открывает дверь игрока: токен в `hexlive-player.txt`, единый
реестр §145.4 создаётся один на процесс, как только открыта хоть одна дверь
(`--control` или `--mcp`). Фоновый `LeaseSweepAsync` (раз в ~5 с) возвращает
колонисток истёкших лизов под ИИ — всегда через СВЕЖИЙ `worlds.Host`.
Событие `WorldSupervisor.WorldSwapped` чистит реестр и заводит зеркало
хроники MCP на новом хосте (иначе `read_events` после «новой колонии» молча
пустел). `WorldHost.EncodeEvents` фильтрует по `IsWireRelevant`. MCP-тулы
покрывают весь §121.9-паритет (talk_to, aid_person, treat_limbs, self_action,
carry/put_down/put_person_in_bed, manage_inventory, transfer_inventory,
transfer_container, prey_person/abuse_person за тем же тёмным выключателем);
обязательные аргументы каждого тула читаются ДО проверки лиза — отказ «нет
параметра X» обязан приходить и без владения (контрактный гейт каталога).
§149 добавляет рядом `hexlive-players.json`: он живёт дольше лиза,
сбрасывается при world-swap и передаёт каждому viewer только его собственный
список через handshake v9.

### §145.6 Server-only commit компаньона

`RecordCompanionTurnCommand` — ещё один конкретный тип общей шины, с command
wire v4 и обязательным codec sample. Он несёт npcId, turnId, trigger, reaction,
короткое intentSummary, до трёх memory upsert и необязательный journalText.
Исполнитель проверяет профиль `masha`, размеры и enum до мутации; replay не
применяет bond второй раз. Игровому клиенту эта команда запрещена как
server-only, а аутентифицированный MCP-шов может отправить её напрямую. Только
voice-trigger применяет таблицу Social/Familiarity/Trust/Affinity §159;
heartbeat и critical сохраняют намерение/память без изменения связи с игроком.

§160 прекращает server-side личный commit. Generic Social остаётся
типизированной идемпотентной командой шины, а intent/relation/journal —
эфемерный read-model attachment. `RecordCompanionTurnCommand` читается только
для совместимости старого save/command wire и не доступен новым MCP tools.

Админские исключения и отдельная голосовая шина описаны в §161; обычные
игровые права и требования этого раздела сохраняются.
