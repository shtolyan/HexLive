## §162 Лобби создания мира на удалённом сервере

### 162.1 До загрузки игры

«Новая игра на сервере» открывает UI Toolkit-лобби. Администратор входит существующим
паролем сервера; player token не даёт права создавать или переключать миры.
Сценарий и seed определяют реальную карту и готовые лагерные якоря. Лобби показывает
карту, состав выбранного лагеря и 3D-примерочную. Черновик хранится на клиенте отдельно
для каждого адреса сервера, пароль и административная сессия в черновик не входят.

### 162.2 Конфигурация

WorldCreationConfig v1 хранит имя, worldId, seed/mode, creatorPlayerId, свой лагерь,
лагеря и персонажей, персональные правила населения. Лагерь выключен — нет дома,
стартовых жителей и прибытий. Включённый пустой лагерь может пополняться. Интервал
0 выключает будущие прибытия, не стартовых жителей. Морские волны Islands отдельны.
Потолок мира 1..256, лагеря 0..потолок мира, интервалы 0..3650 календарных дней.
Карточки отключённых персонажей сохраняются; npcId 1..999 не пересекает полосы
периодических прибытий. Как минимум один включённый герой своего лагеря управляемый.

Все отмеченные герои принадлежат создателю; другие подключения — зрители.
Право не означает принудительный ручной режим. Новые жители по умолчанию NPC;
ControlArrivals включает владение прибывающими в свой лагерь. Прежняя выдача одного
свободного персонажа сохраняется для миров без WorldCreationConfig. При потере
назначенных героев создатель получает свободных живых кандидатов на следующем
подключении (§149.6); уведомления о смерти и знакомство сохраняются до подтверждения.

### 162.3 Персонаж

Тело, материалы, глаза, причёска, цвет волос, голос и имя независимы. Molly — «Худая»,
Marta — «Спортивная», Jana — «Пухленькая», Jolly — «Изящное», мужские тела подписаны
как мужские. Доступны совместимые опубликованные ассеты. Выбранный комплект заменяет
сценарную одежду; остальные предметы сценария сохраняются. Предпросмотр использует
NpcActorView и игровой загрузчик одежды. Семь характеристик и все девять текущих
навыков (включая Атлетику) задаются в 0..1 без бюджета, черты — из TraitSet.
HairColour пусто сохраняет старый сидированный выбор, prototype означает исходный
материал причёски. Цвет хранится в NPC, blob v72 и snapshot v41; handshake v14
передаёт worldId и рецепт генерации. Старые blobs v66..71 остаются читаемыми.
Стартовые точки подбираются PopulationArrivalMath в семи гексах: якорь + кольцо 1,
радиус гекса 1.5 wu, расстояние соседних центров sqrt(3)*1.5 = 2.598 wu.
Схема: [появление в лагере](../Docs/PopulationArrivalDiagram.svg).

Примерочная организована как Wardrobe Test: слева постоянные имя, лагерь и живой
предпросмотр; справа «Внешность» и «Параметры». Внешность разделена на Тело, Кожу,
Глаза, Волосы, Бельё, Одежду, Верхнюю одежду и Сумки. Кожа 1..4 соответствует
Molly/Marta/Jana/Jolly; названия и номера не меняют идентификаторы ассетов.
Плитки используют игровые ассеты и иконки. Одна модель одежды занимает одну плитку,
её расцветки и снятие находятся в постоянной панели под каталогом. Волосы используют
ту же панель вариантов. Поиск, прокрутка и выбор сохраняются отдельно для вкладок.
При смене тела удаляются только несовместимые части образа с сообщением пользователю.

Idle проигрывается непрерывно. Только смена тела пересоздаёт модель и Animator;
кожа, глаза, волосы и одежда применяются к существующей модели. Запоздавшая загрузка
не отменяет более поздний выбор. Черновик записывает конкретный выбранный образ.
ПКМ вращает камеру, колесо приближает, средняя кнопка смещает обзор только в области
предпросмотра. Есть восстановление ракурса; начальный кадр вмещает фигуру с запасом.
Фон соответствует игровому портрету, основной и заполняющий свет мягкие, локальные.
Отладочные инструменты и Editor-only загрузка Wardrobe Test в лобби не переносятся.

### 162.4 Миры на хосте

WorldLibrary хранит worlds/<id>/world.sav, creation.xml, players.json и simdata.json.
active.json указывает единственный активный мир. Старый save импортируется копией,
исходник не удаляется. Неактивные миры не тикают. Переключение сохраняет старый мир
на границе тика; новый подготавливается и сохраняется до публикации. При ошибке
подготовки старый продолжает работу. Административные пароли и токены общие для хоста.
API /api/worlds/v1 даёт login, capabilities, preview, validate, создание, операции,
список и activate. Повтор requestId не создаёт второй мир. Клиент проверяет состояние
операции, затем подключается обычным /watch. Неверная конфигурация возвращает список
ошибок с путями полей. Клиент и сервер строят топологию из одной конфигурации.

Назначенные id сохраняются в blob v72 для мира лобби отдельно от лагерной принадлежности.
Переход героя между обычными лагерями не снимает владение; прибывший получает
постоянное право один раз при появлении, если включён ControlArrivals. Изменение
живого управляемого состава обновляет права существующих зрителей реконнектом.

Предпросмотр фиксирует конкретную расцветку волос, включая сценарный сидированный
вариант; кнопка случайного выбора использует только опубликованный серверный каталог.
Проверка одежды использует WearSlotCatalog.Occupies (§52), а не грубые зоны защиты
Covers: сапоги, чулки и набедренная вещь могут занимать разные слоты.
Проверка конфигурации до запуска строит стартовый мир без тиков; отсутствие свободной
точки возвращает characters[index].camp/noFreeSpawn.
Публикация active.json — точка фиксации создания. Готовность save сама по себе не
считается успешным переключением. Повтор requestId после отказа записи активирует
подготовленный мир; повтор уже завершённого запроса не переключает текущий мир.
