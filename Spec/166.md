## §166 Единый ключ закрытого теста и выбор официального сервера (iteration 166)

**Фаза 1 (2026-09-19):** развёртывается только Сингапур. Нью-Йорк отключён
в списке Player и не опрашивается. Его обновление требует отдельной команды.
Ключ един для игры, админки и Flashback; права изменяются без перевыпуска.

Закрытый тест использует один персональный ключ на всех официальных серверах.
Общий серверный токен и самостоятельно выбранный клиентом id остаются только
в legacy/dev-режиме сервера без `HEXLIVE_IDENTITY_URL`.

### §166.1 Личность и ключ

Отдельный процесс `HexLive.Identity` в Сингапуре хранит единый реестр аккаунтов.
`accountId` — внутренний постоянный GUID; ключ — случайный секрет доступа к нему,
а не второе имя пользователя. Клиент вводит только ключ. Игровой сервер сам
получает accountId по HTTPS, не доверяет заголовку `X-HexLive-Client-Id` и использует
этот accountId в существующем реестре назначений §149 и лизах §145.
Назначения NPC остаются локальными для мира: одинаковый аккаунт в Нью-Йорке и
Сингапуре не означает перенос персонажа между независимыми мирами.

Админка: вход по ключу с `keys.manage`, имя, флажки прав, выдача, замена и отзыв ключа. Ключ
показывается один раз; на сервере хранится SHA-256 от 256 случайных бит.
Форма входа убирает внешние пробелы при вставке ключа. Ошибки ключа, прав,
устаревшей формы и ограничения попыток показываются на странице с повторным
вводом, а не пустым HTTP-ответом; статусы 401/400/429 сохраняются.
Замена сохраняет accountId, старый ключ сразу перестаёт проходить проверку.
Новые подключения с неверным/отозванным ключом получают 401; недоступность
authority — 503, без anonymous/shared-token fallback. Активный сокет перепроверяется
каждые 60 секунд и закрывается при отзыве либо недоступности authority.
Первый ключ владельца выдаётся только локальной командой bootstrap в пустой
реестр и записывается в приватный файл, не в журнал. Формы защищены anti-CSRF, сессии — Secure/HttpOnly/SameSite cookies.
Реестр пишет один процесс, атомарной заменой файла с flush; второй процесс с тем
же каталогом не запускается. Нечитаемый реестр не заменяется пустым.

Будущие Google/Apple login должны связывать внешнюю личность с тем же accountId
и выпускать/заменять credential через эту authority. OAuth пока не реализован.
Существующие legacy назначения автоматически не привязываются к новому ключу:
оператор должен подтвердить владельца перед миграцией, иначе получится захват аккаунта.

### §166.2 Клиент закрытого теста

В Player включён простой вход: ключ → два официальных сервера. Ключ сохраняется
через macOS Keychain / Windows DPAPI и не записывается в PlayerPrefs или аргументы
процесса. В PlayerPrefs остаётся только несекретный accountId для совместимости
с Agent Studio. При перезапуске ключ проверяется снова, повторный ввод не нужен.
«Сменить ключ» доступно из меню. Недоступность authority не удаляет сохранённый ключ.

Локальная игра, произвольный адрес и создание мира скрыты в Player, код сохранён
и доступен в Unity Editor. Старые аргументы режима/token/client-id в Player не
обходят новый вход. Лаунчер не встраивает общий ключ и не передаёт игровой сервер
или токен при запуске. Он открывает меню игры.

### §166.3 Статус серверов

`GET /api/servers/v1/status`: зелёный `available`; жёлтый `busy`, если EMA времени
шага (0.9 предыдущего + 0.1 текущего) достигла 80% бюджета тика с учётом скорости;
красный `unavailable`, если сервер не отвечает за 5 секунд, отдаёт некорректный
статус или не настроен на общую authority. Клиент опрашивает каждые 10 секунд.
Жёлтый допускает подключение, красный отключает кнопку. Это простой индикатор
вычислительной нагрузки, не оценка пинга и не обещание отсутствия задержек.

### §166.4 Обновления и развёртывание

Найденная система обновлений — Windows Launcher, HTTPS-манифест и ZIP на сервере
Сингапура с проверкой размера и SHA-256. Google Drive как источник пока не настроен.
Инструкция развёртывания authority и переключения Сингапура:
`Docs/ClosedTestRelease.md`. Публикация требует отдельной проверки реальных
сервисов, DNS/TLS, Client UI и назначения персонажей; наличие кода не равно deploy.

### §166.5 Единый доступ по изменяемым правам

Центральный аккаунт содержит изменяемые права: `game.play`, `bugs.create`,
`bugs.read`, `bugs.manage`, `server.admin`, `keys.manage`. Ключ удостоверяет
аккаунт, полномочия берутся из актуального реестра. Доступ к игровой админке
сам по себе не разрешает выдавать ключи или менять чужие права.

Редактирование прав защищено ревизией и журналируется. Снятие права не требует
перевыпуска ключа. Право играть перепроверяется в активной сессии не реже раза
в 60 секунд, привилегированная операция — перед выполнением, включая отложенные
команды и подтверждения. Старые веб-сессии и локальный UI не сохраняют снятые права.

Flashback проверяет `bugs.create` независимо от `game.play`. Форма создания
работает без общей очереди, если `bugs.read` не выдано. Существующие ограничения
workflow агентов сохраняются. Замена клиентского токена без изменения Flashback
не считается реализацией. Центральные ключи Flashback проверяются при каждом запросе и записи;
существующие device keys автоматизаций сохраняются на время миграции.
Браузерные сессии центральных ключей Flashback после перезапуска требуют
повторного ввода ключа; секреты хранятся только в памяти процесса.

### §166.6 Несовместимый протокол и обязательное обновление

Player при старте, ещё до чтения ключа/авторизации, параллельно проверяет
`GET /api/client/v1/compatibility` включённых официальных серверов (timeout 5 секунд).
В фазе 1 включён только Сингапур.
Ответ содержит текущий `Handshake.ProtocolVersion` и не кэшируется. Проверка
повторяется перед подключением. Недоступность сети не считается несовпадением.
Если доступный сервер сообщает другой протокол, вместо входа показывается
«Внимание: протокол не совпадает. Вам нужно обновить клиент» с двумя действиями:
«Обновить» и «Выход». Продолжить игру/пропустить эту проверку нельзя.
Отключённые регионы не участвуют в этой проверке; для первой фазы это Нью-Йорк.

Старый сервер без HTTP endpoint или смена версии во время подключения также
защищены проверкой первого int32 handshake до чтения остального формата.
Несовместимость переводит загрузку в тот же обязательный экран, без reconnect-loop.

На Windows «Обновить» запускает упакованный рядом с Player `HexLiveUpdater.exe`
через Win32 `CreateProcessW` (managed `Process.Start` не реализован в IL2CPP).
Ошибка запуска записывается в Player.log и показывается вместе с причиной.
Игра закрывается только после успешного создания процесса обновлятора.
Обновлятор запускается с PID игры и требуемым протоколом. Updater ждёт её выхода
(до 30 секунд, без принудительного завершения процесса), получает latest,
требует точного совпадения `playerRelease.protocolVersion`, скачивает/проверяет
SHA-256 и размер ZIP, устанавливает в новый каталог и запускает обновлённую игру.
Если совместимый релиз ещё не опубликован, показывает ошибку с возможностью
повторить; неподходящая версия не запускается. Старая установка сохраняется
до атомарной записи install-state. Повторная загрузка поддерживает HTTP Range.

Windows builder упаковывает updater и ZIP, добавляет размер, hash и протокол
в manifest; публикация раздаёт только публичную release-часть, без bug snapshot.
Веб-маршруты releases подключены в Program. Ранее реализация endpoints лежала
отдельно, а builder не создавал ожидаемый publisher-ом `playerRelease`.

macOS: экран блокировки общий, но автоматический установщик этой платформы
пока отсутствует; кнопка сообщает о необходимости официального дистрибутива.
До реализации подписанного macOS updater это не считается завершённой
поддержкой автоматического обновления macOS.

### Веб-интерфейс управления ключами

Админка использует тёмную палитру Flashback с фиолетовым акцентом. Вход, выдача
и карточки участников оформлены отдельными панелями. Права подписаны по-русски
с краткими пояснениями; есть поиск по имени, статусы и счётчики. После сохранения
прав и отзыва показывается подтверждение. Отзыв требует явной отметки в форме.
Ошибки операций и конфликт ревизий показываются внутри интерфейса с возвратом
к списку. Интерфейс адаптируется к узкому экрану.

### Фаза 2: проверка обновления Windows

Клиент 0.1.111 и Сингапур используют протокол 19; формат пакетов и игровая
логика относительно протокола 18 не меняются. Установленный клиент 0.1.110
остаётся прежним до запуска обновления самим тестировщиком. Сначала публикуется
совместимый Windows ZIP, затем переключается протокол Сингапура.
Меню входа и серверов расположено по центру загрузочного экрана. Ключ скрыт
точками на светлом поле с тёмным текстом; «Показать ключ» / «Скрыть ключ»
переключают видимость. Есть кнопка «Вставить» и меню вставки по правой кнопке.

Agent Studio использует тот же персональный ключ и account ID (§163.2). Ключ хранится
один раз в защищённом хранилище ОС; каталог MCP и команды требуют серверной
авторизации. В форме выдачи ключа нет выбора «игрок / агент»: назначаются права.
