# Проверка диалога Маши

Стенд использует `AgentProviders`, `AgentPromptBuilder`, `MashaMemoryWorkspace`,
выбранную в Studio модель и настоящий серверный каталог аргументов MCP.
Сам MCP не вызывается, действия не исполняются, TTS отключён. Память синтетическая;
рабочий workspace Маши не изменяется. Доступ к выбранной интеграции требуется.

При закрытом Unity Editor сначала опубликовать стенд в **отдельную папку**:

```sh
dotnet publish Tools/HexLive.AgentDialogueEval -c Release -o Build/DialogueEvalRunner
dotnet Build/DialogueEvalRunner/HexLive.AgentDialogueEval.dll --run /absolute/path/to/profiles.json Build/AgentDialogueEval/review 60
```

Не пересобирать используемую папку до окончания прогона. `run.json` фиксирует
модель, reasoning и SHA-256 общего ядра. `responses.json` сохраняется после каждого
ответа: исходная реплика, состояние, результат, длительность, проверка формы
аргументов и ошибка валидации, если она возникла. Секреты и скрытые рассуждения
не записываются. Не запускать стенд без явного запроса: он делает реальные модельные вызовы.

По умолчанию: 5 режимов отношений × 6 последовательных сцен × 2 запуска = 60 ответов.
Это 30 комбинаций, а не 30 независимых сюжетов. Внутри каждой последовательности
передаются последние 6 строк истории; отношения фиксированы условиями теста,
а результаты физических действий задаются следующим синтетическим состоянием.
После числа ходов можно передать один режим (`close`, `affection-only`, `trust-only`,
`slight`, `dislike`) для короткой диагностической проверки. Она не заменяет полный прогон.

`actionContractValid` проверяет только форму, типы и обязательные аргументы.
Он **не означает**, что реальная симуляция примет действие, что путь проходим,
либо что модель соблюдает характер. Эти свойства оцениваются отдельно.

## Ручная оценка

Для каждого ответа отметить:

- `style`: разговорная резкость/точечная колкость, а не безличный отказ; мат не обязателен в каждой строке.
- `relationship`: тепло соответствует симпатии, самостоятельность и опора на совет — доверию;
  оценка нового события не путает потенциальный риск с уже причинённым серьёзным вредом.
- `decision`: нет явно опасного или бессмысленного решения в заданной сцене.
- `facts`: не придуманы состояние, личные сведения, предметы или выполненные действия.
- `variety`: в последовательности нет механического одинакового вступления или оскорбления.
- `joint`: одновременно прошли `style` и `relationship`. Отклонённый ответ — не успех.

Порог принятия: минимум 54/60 по `joint`, без критических ошибок поведения.
Оценку делает человек/рецензент по всем ответам, не regex и не наличие мата.
CSV в `Review/` содержит итог каждой строки и замечания. Это внутренняя оценка Codex,
не новая пользовательская авторская апробация. Отдельная живая игровая приёмка нужна.

Авторские примеры взяты только из одобренных сцен исходного разговора;
использованы речевые фрагменты без литературных жестов. Они иллюстрируют стиль,
но не импортируются в память. Начальные ответы, которые пользователь критиковал,
в набор не включены. Подробный результат — в `Server/HexLive.AgentStudio/MASHA_DIALOGUE_REVIEW.md`.
