# Восстановление документов памяти (§163.3, bug #373)

Остановить Studio и CLI, сохранить полную резервную копию workspace. При закрытом
Unity Editor собрать `dotnet build Tools/HexLive.MemoryRepair -c Release`, затем
запустить собранный `HexLive.MemoryRepair.dll --repair /absolute/workspace`.

Программа использует штатную миграцию MashaMemoryStore, не подключается к миру,
не читает credentials, не запускает модель и не меняет отношения без ранее
сохранённой явной редакции. Удаляются только точные дубли автоматической секции;
предыдущие документы остаются в `.history`. Не запускать одновременно со старым
Studio: он ещё может писать по старым правилам.

Редактирование USER.md, MEMORY.md и управляемых собственных заметок SOUL.md через
Studio теперь оставляет операцию в `.state/document-edits`. Она применяется один
раз перед следующим контекстом/сохранением или при загрузке workspace. До применения
сохраняется backup состояния. История и iPhone-импорт не удаляются, но явно удалённые
активные факты фильтруются из последующего recall. Это не обещает, что модель никогда
не выскажет похожую мысль другими словами.

Ручные комментарии вне секции остаются авторскими заметками. Архивные дневники,
импортированные исходники и технические поля миров не являются универсальным
редактором состояния симуляции. Правки внешним редактором сохраняются как ручной
текст прежним механизмом; для синхронизации фактов используйте Save в Studio.
